# Telegram Bot Message Catalogue

**Code snapshot reviewed:** 1 September 2026
**Purpose:** catalogue the text that the JBL/Jawabu Telegram bot sends or replies with, especially messages visible in operational groups.

## How to read this catalogue

This is a code-backed inventory of Telegram messages. It includes:

- replies sent into the group where a command or tagged message was received;
- pinned Mini App launcher posts published into configured groups;
- automatic group notifications;
- private staff alerts, onboarding messages, and technical-governance notices;
- Telegram inline-button labels and native command-menu descriptions.

It does **not** include:

- text rendered only inside a Mini App or Django Admin page;
- HTTP API JSON messages that are not sent through Telegram;
- log, Sentry, or management-command console messages;
- text generated by Telegram itself, such as service notices;
- file contents or Google Sheets/Drive content.

Text in `{braces}` is inserted at runtime. Optional blocks are marked as such. Some error details come from parsers or integrations and therefore cannot be enumerated as a single fixed sentence.

The Python code remains the source of truth. When wording changes, update this catalogue with the corresponding message builder.

## Delivery and visibility rules

| Delivery type | Who can see it | Behaviour |
|---|---|---|
| Group command reply | Members of the originating Telegram group | Sent as a reply to the triggering Telegram message. |
| Group ingestion reply | Members of the originating Telegram group | Acknowledges, rejects, or summarizes a complaint/import. |
| Group launcher | Members of one configured group | Sent or edited as `JBL Apps`, then pinned silently when the bot has permission. |
| Group notification | Members of a selected operational group | Sent without requiring a group command. |
| Private staff message | One linked Telegram staff account | Used for TAT tasks, onboarding, access governance, and technical completion notices. |

Messages tagged `ignored` are not sent to Telegram. Untagged messages are normally ignored in workflow groups; the bot replies only when tagged, invoked by a supported slash command, or handling an allowed reply/media flow.

## 1. Shared group launcher and new-member welcome

### Pinned group launcher

**Audience:** configured Telegram group
**Trigger:** an administrator publishes or refreshes the group launcher.

```text
JBL Apps
Choose a tool for this group.
```

Configured buttons are arranged two per row and may include:

- `TAT Tracker`
- `SPIN / CRB`
- `Order Approval`
- `Pipeline Portal`
- `Complaint Cases`
- `Loan Origination`

### Public welcome for a new group member

**Audience:** originating configured group
**Trigger:** one or more human accounts join outside the governed staff-onboarding handoff.

```text
Welcome {names}.

Use the buttons below to open the tools configured for this group.
If a button does not open for you, ask an admin to add your Telegram account to the workflow staff list.
```

The attached buttons are the same configured group launcher buttons. Up to three names are shown; additional members appear as `and {count} more`. A staff member already handled through governed onboarding does not receive this public welcome.

## 3. Complaint intake acknowledgements

The common reply renderer sends the following messages after a tagged complaint is processed.

### Saved successfully

```text
OK. Message received and saved successfully
Case ID: {source_message_id} (use this for /update)
Captured:
{field}: {value}
Warnings:
- {warning}
```

The Case ID, Captured, and Warnings blocks appear only when available.

### Rejected for missing fields

```text
Rejected. Complaint was not saved because required fields are missing.
Missing required fields:
- {field}
Captured:
{field}: {value}

Required complaint fields:
- NAME
- TEL or ID
- NATURE OF THE PROBLEM
```

### Saved but register publication failed

```text
Warning: Message saved to database but could not sync to the register at this time. It will be retried automatically.
Case ID: {source_message_id} (use this for /update)
Captured:
{field}: {value}
Warnings:
- {warning}
```

### Saved with review notes

```text
Warning: Message saved with review notes.
Case ID: {source_message_id} (use this for /update)
Captured:
{field}: {value}
Warnings:
- {warning}
```

### Partially processed

```text
Warning: Message partially processed (some fields were not recognised)
Case ID: {source_message_id} (use this for /update)
Captured:
{field}: {value}
Warnings:
- {warning}
```

### Duplicate, skipped, and general failure

```text
Warning: This message has already been processed.
```

```text
Warning: Message skipped - no text content found.
```

```text
Error: This message could not be processed. Please check the format and try again.
```

Any unrecognized result status falls back to:

```text
Message received (status: {status})
```

## 4. Complaint search and reporting commands

Every case row in these replies uses this shape:

```text
{number}. {DD/MM/YYYY|no date} | {CUSTOMER NAME}
   Tel: {phone|no phone} | Customer ID: {id|no customer ID} | Status: {status|status not set}
   Problem: {description|no problem description recorded}
```

### Recent and date commands

| Command | Success heading | Empty result |
|---|---|---|
| `/last [n]`, `/recent [n]` | `Latest {count} case(s):` | `No cases found for this group yet.` |
| `/today` | `Today's cases ({count} shown):` | `No cases found for this group today.` |
| `/week` | `This week's cases ({count} shown):` | `No cases found for this group this week.` |
| `/unsynced [n]` | `Latest {count} unsynced case(s):` plus `Sync error: {error}` | `No unsynced cases found for this group.` |

### Field lookups

`/phone {value}` and `/id {value}` reply with:

```text
Cases for {phone|customer ID} '{query}' ({count} shown):
{case rows}
```

Empty and no-result forms are:

```text
{Phone|Customer Id} lookup value cannot be empty.
```

```text
No cases found for {phone|customer ID}: {query}
```

### Status, quality, and risk views

| Command | Success heading | Empty result |
|---|---|---|
| `/open [n]` | `Latest {count} open case(s):` | `No open case(s) found for this group.` |
| `/pending [n]` | `Latest {count} pending case(s):` | `No pending case(s) found for this group.` |
| `/closed [n]` | `Latest {count} closed case(s):` | `No closed case(s) found for this group.` |
| `/missing phone|id|name [n]` | `Latest {count} case(s) missing {field}:` | `No cases missing {field} found for this group.` |
| `/lowconfidence [n]` | `Latest {count} low-confidence/incomplete case(s):` plus `Reason: {reasons}` | `No low-confidence or incomplete cases found for this group.` |
| `/risk {level} [n]` | `Latest {count} {level} risk case(s):` | `No {level} risk cases found for this group.` |
| `/stale [days]` | `Stale cases older than {days} day(s) ({count} shown):` plus `Age: {days} day(s)` | `No stale cases older than {days} day(s) found for this group.` |
| `/errors [n]` | `Latest {count} sync error case(s):` plus `Error: {error}` | `No sync errors found for this group.` |

Low-confidence reasons can be `partial processing`, `missing name`, `missing phone`, and `missing description`.

### Duplicate and top-count reports

```text
Duplicate hints in the last {days} day(s):
phone {value}: {count} case(s)
customer ID {value}: {count} case(s)
```

or:

```text
No duplicate phone or customer ID hints found in {days} day(s).
```

```text
Top {regions|issues} in the last {days} day(s):
1. {value}: {count}
```

or:

```text
No {regions|issues} found in the last {days} day(s).
```

### Summary

```text
Summary for {today|this week (from DD/MM/YYYY)}:
Total: {count}
Open/not closed: {count}
Pending status: {count}
Closed: {count}
Unsynced: {count}
Sync errors: {count}
```

### Case detail and search

```text
Case {source_message_id}
Date: {date}
Customer: {CUSTOMER}
Phone: {phone|not set}
Customer ID: {id|not set}
Region: {region|not set}
Status: {status|status not set}
Synced: {yes|no}
Description: {description}
```

If not found:

```text
Case {source_message_id} was not found in this group.
```

Search replies are:

```text
Search results for '{query}' ({count} shown):
{case rows}
```

```text
No cases found for search: {query}
```

```text
Search query cannot be empty.
```

## 14. Current wording and delivery issues exposed by this inventory

This section records current behaviour; it does not redefine it.

1. **Complaint references are inconsistent.** Complaint creation, `/case`, `/update`, ambiguous-case guidance, and search rows still expose the internal/source `MSG_...` identifier and instruct staff to use it. The Complaint Cases Mini App now has the staff-facing sequential `CMP000001` reference, but these bot replies have not been migrated to it.
2. **The sequential complaint reference is not searched by the legacy bot `/search` query.** The command searches source message ID, name, phone, customer ID, complaint description, and raw text.
3. **`/sync` is advertised inconsistently.** The native menu and `/help` say it refreshes from Google Sheets, while the command intentionally says Sheets import is disabled.
4. **The Jawabu fallback mentions the wrong command.** It tells users to send `/spin`, even though `/spin` is the SPIN workflow form command.
5. **TAT batch success is not rendered.** `process_tat_batch_rows()` builds a detailed `reply_text`, but returns status `tat_batch_processed`; the common renderer does not consume that status and sends `Message received (status: tat_batch_processed)`.
6. **Some operational replies expose technical configuration.** `/group`, `/health`, `/errors`, `/unsynced`, import summaries, and some integration errors reveal sheet IDs/tabs, sync state, and error text to the group. They should be treated as support diagnostics, not general user help.
7. **Legacy complaint status terms differ from the Mini App.** Bot commands and updates use `Open`, `In Progress`, and `Closed`, whereas current Complaint Cases user-facing terminology is `Pending` and `Resolved`.
8. **The proactive Jawabu approval destination is not tied to the approved record's originating group.** It selects the first configured Jawabu group and otherwise falls back to the default chat.
