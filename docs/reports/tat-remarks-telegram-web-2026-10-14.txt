WHAT CHANGED

1. Stage rows separate elapsed time, target and result with visible separators.
   Complete items wrap together. Existing live counters, sizes and layout remain.
2. Ordinary timestamp activity displays the recorded time once. Dropdown outcomes
   retain their value row; actual date corrections remain under Date correction.
   Source audit evidence is unchanged. Other Mini Apps' timeline behavior is unchanged.
3. All authorized staff who can view an in-scope TAT case may append a remark,
   including after Declined or Disbursed. Deleted/unresolved/closed-Pilot cases
   remain read-only. Actor, applicable roles and Nairobi server time are retained.
   Existing notes survive. Text, actor/time footer and a line separate comments.
4. The composer starts empty and retains failed input. Its request key survives a
   lost response. Same-key/same-actor/same-text retries return the existing event;
   a changed actor or text conflicts. Input is 1-5,000 trimmed characters.
5. A comment changes only the notes projection, not workflow revision, update
   time, stages, targets, completion, responsibility, notifications or signatures.
   The old replace-remarks update is rejected instead of overwriting history.
6. Event-keyed IntegrationOperations use the existing TAT processor. Sheet writes
   locate one immutable Case ID in its named column and update only literal notes
   text. Reordered columns and the explicit legacy Remarks alias are supported;
   ambiguous headers, duplicate IDs or missing rows stop the write. Stage
   publishers use current locked notes rather than their stale object copy.
7. Active Superusers can requeue failed remarks using Retry selected TAT remark
   Sheet updates in Integration Operations Admin. The retry is audited, makes no
   provider call and leaves other operation types untouched.
8. Only allowlisted Mini App HTML controllers permit self and
   https://web.telegram.org as ancestors. TAT, Complaints, Portal, Origination
   and the reviewed older Mini App controllers are covered, including deep links.
   Admin, unrelated pages and JSON retain protection. Authentication is unchanged.
9. TAT download GET and HEAD expose the same filename, content disposition, type,
   length and private/no-store policy, plus Telegram Web CORS. The SDK receives
   file_name, not an alternate spelling. A named fallback handles unsupported,
   cancelled, failed or unanswered download requests; requested is not downloaded.

UNVERIFIED / LIMITS

No production database, deployment, Google Sheet, Drive file or Telegram account
was mutated. Physical Telegram Web launch and its real download dialog require
post-deployment checking; browser SDK mocks are not proof of device behavior.
The header fix follows Telegram's current DownloadFileParams contract:
  https://core.telegram.org/bots/webapps#downloadfileparams

Per-case publication locking prevents stale note overwrites but may briefly
delay a simultaneous canonical write on that same case. Provider failure never
undoes an already committed note. Schema repair and exhausted-retry recovery are
explicit Admin actions, not automatic configuration repair.

Local Python 3.14 differs from deployed Python 3.12. The full repository suite
and production providers were not run. See KNOWN_GAPS.md for the evidence scope.
